# Digital twin project context

- This is an independent React + TypeScript + React Three Fiber application. Do not modify the MATLAB simulations or unrelated papers when working on the viewer.
- Run commands from `CAMBRIDGE/digital_twin` with Node.js 22.22 or later in the Node 22 line. Install locked dependencies with `npm ci`.
- Development: `npm run dev`. Production verification: `npm run build`. Unit tests: `npm test`. Browser tests: `npm run test:e2e`.
- Browser tests use Playwright Chromium and a local server on port 5173. Install the browser with `npx playwright install chromium` when absent; set `PLAYWRIGHT_SKIP_BROWSER_GC=1` to retain other cached browser versions.
- `src/model` owns configuration, layout generation, canonical coordinate conversion, and the geometry-only `opticalScene` adapter. `src/state` owns persistence/display sampling. `src/scene` owns rendering. `src/components` owns controls/charts.
- `src/science` is the user-reviewed scientific boundary for optical models, physical defaults, noise, unit conversions, and future estimators. Its runtime modules must remain pure and import only science siblings, never React, Three.js, DOM, or application modules. Flag scientific formula/default/assumption changes explicitly for user review.
- Scientific verification: `npm run test:science`. `npm run reference:matlab` regenerates 40 frozen LOS cases using the original `../simulations/PoC` MATLAB functions without modifying them; MATLAB must be available on PATH. Reference generation was verified with R2026a. Keep the generator and reference JSON in `src/science/validation`.
- Keep the canvas full-window, without branding/header/footer bands. Settings are hidden on load and overlay the scene on the left without resizing/remounting it; export belongs in settings. Align the panel with its trigger and balance the outer margins. Only the camera toolbar floats at the bottom, with transparent pointer-pass-through space around it.
- Workspace palettes live in `src/theme/themes.ts` and are persisted as `appearance.theme`. Chalk is the default; Pure White has three `#ffffff` background stops and replaces legacy Lavender. Preserve valid saved choices and migrate saved Lavender to Pure White. Use semantic CSS variables and matching 3D guide accents; changing a palette must not change LED power/temperature, physical materials, geometry, camera or positioning data.
- Start and reset the isometric camera with immersive framing: 1.6 times the full-room fit, capped by viewport width. Keep the separate Fit room to view action, and top/front presets, fully fitted. Framing is transient camera state, not physical room geometry.
- Perspective is an alternative real 66-degree camera at entry/eye level. Switch cameras without remounting Canvas; Reset camera resets the current view. Interior walls use camera-position cutaway, with an opaque ceiling and subdued studio fill. Dimension guides and ghost-ceiling controls are temporarily unavailable in Perspective without mutating saved display settings.
- Domain coordinates are right-handed `[x, y, z]`, Z-up, in metres, with the floor centre at the origin. Three.js coordinates are `[x, z, -y]`; use the canonical model conversion rather than duplicating it.
- Room geometry, LED positions, guides and camera bounds must share the centred coordinate frame. Keep regression tests for this invariant.
- Receiver geometry is defined in `src/model/receiver.ts`: the cylinder is 0.1 m diameter and 0.08 m high; the drone is 0.28 x 0.28 m at zero yaw and 0.06 m high, including guards/landing feet. Both carry a 0.01 x 0.01 x 0.002 m PD on top. `receiver.position` is the active platform body centre; the default is X = Y = 0, Z = 0.30 m. Use platform/yaw-aware bounds during both drag previews and normalization, including the swept rotor/guard radius. Derive PD position and export geometry from the active platform. `receiver.yaw` is degrees around world Z and does not tilt the PD.
- `receiver.platform` selects Cylinder or Drone; old scenes migrate to Cylinder and retain their pose. `rotorsSpinning` is a saved visual preference. Animate only rotor refs, never receiver/PD position or yaw; continue demand rendering only while the visible drone is spinning. Pause for hidden documents/reduced motion and stop the animation loop when returning to Cylinder.
- Only configured, powered LEDs cast scene shadows. Studio/environment fill lights must not cast shadows; do not add synthetic projected contact shadows that create extra receiver or luminaire silhouettes.
- Receiver dragging uses transient preview state and commits once on release. Keep RX labels as understated as LED labels. Single clicks only select; double-clicking the body/tag opens the X/Y/Z HUD. Hide that HUD during any drag while keeping its captured DOM node mounted, and retain projection guides. XY body/tag drag and world-axis handles must lock OrbitControls synchronously; Escape, cancellation, blur and view changes must discard the preview and restore camera navigation. Consume Escape during an active drag so it does not also close a focused analysis panel. Clamp the entire cylinder and PD within room bounds. Preserve valid saved receiver poses across reloads; legacy configurations gain a receiver at (0, 0, 0.30 m).
- The MATLAB baseline in `../simulations/PoC/poc_params.m` uses a 3 x 3 m floor, ceiling LED at 2 m, and 0.405 W optical power. The viewer defaults to four LEDs for the visual prototype.
- Rendering intensity and colour temperature remain illustrative, not calibrated radiometry. RSS comes exclusively from the separate Lambertian LOS science model. It currently assumes an unobstructed path, bare upward-facing PD and ideal LED-channel separation; no NLOS, physical reflections, electronics, hardware connection or positioning estimator is implemented.
- Optical defaults match `poc_params.m`: half-power angle 45 degrees, active area 26.4 mm², FOV half-angle 85 degrees, optional optical-domain AWGN variance 3e-14 W² per sample averaged over 1000 independent samples. Noise is off by default. The 10 x 10 mm drawn PD is a package; active area is independently configurable. Responsivity is not part of incident optical power in watts.
- RSS inputs use LED anchor coordinates as optical reference positions, excluding decorative housing/spotlight offsets; use the actual derived PD centre, not the platform centre. Camera, palette, rendered shadows and rotor animation must never affect RSS. Yaw alone does not tilt the PD.
- The optional RSS panel samples the live receiver preview at a 20 Hz display rate, not an ADC/carrier rate. It maintains a bounded 20-second/401-sample trace, stops sampling when closed/hidden/paused, and resets trace/RNG when physical parameters change, not on receiver translation or visual changes. Preserve negative Gaussian estimates; never clip them to zero. Default RSS presentation is plot plus LED colour legend; Details reveals controls/readouts without resetting the mounted stream.
- The optional X-Y plan uses equal metre scale and positive Y upward. Share LED colours with RSS and show only ground truth until real estimator outputs are supplied. Stack analysis windows without overlapping or resizing the 3D canvas.
- Programmed drone routes are geometric presentation/motion utilities in `src/model/motion.ts`, not optical models. Circle, figure-eight and raster scan use arc-length sampling with a lead-in from the current pose, bounded for the receiver geometry/yaw. Motion configuration is saved, but playback never autostarts on reload. Pause/finish commits the current pose; paused Play resumes its phase, and Restart rebuilds from the current pose. Hidden-tab time is excluded.
- Feed automatic motion into the same live pose as manual dragging, RSS and the X-Y map. Manual drag must synchronously pause at the exact rendered start position. Pause before editing receiver pose/platform, room dimensions or route settings; optical, appearance and camera changes must not disturb playback. Rotor spin and route translation have independent controls.
- Keep configuration serializable and independently testable. Count, layout and spacing changes clear manual position overrides; shape, power and temperature changes preserve them.
- Avoid runtime asset/CDN dependencies for the initial scene. Materials and reflection lighting are generated locally.
- Dependencies are pinned in `package.json` and `package-lock.json`. npm 10.9.4 can fail with an `edgesOut` error when updating Vitest optional peers; npm 11.10.1 was verified for that update without changing global npm.
